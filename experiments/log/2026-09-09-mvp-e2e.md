# MVP 端到端实测：agy flash-low 翻译论文前 2 页

日期：2026-09-09 · 分支：agy-mvp · 记录人：ZCode session

## 设置

- 文档：FreqFed (arXiv 2312.04432v2)，前 2 页（标题/作者/摘要/引言，双栏）
- 翻译方：`agy --model gemini-3.8-flash-low --effort low --print "$(cat prompt)"`，
  单次调用，prompt 含占位符协议 + 29 行输入（12.4KB），无上下文示例
- 工具链：`python -m babeldoc.tools.agent extract/apply/reconstruct/render`
  （native ONNX 布局，非 MinerU；sheet 语义与原翻译管道一致）

## 结果

| 指标 | 值 |
|---|---|
| extract 段落数 | 29（title 5 / plain text 22 / abandon 2） |
| agy 输出 | 干净 JSONL，无代码块包裹、无解释文字 |
| apply 违规 | **0**（id 对齐 29/29，占位符多重集全对，一次通过） |
| 重试次数 | 0 |
| 产物 | mono PDF 2 页，2345 汉字；残留 `{vN}`/`<style>` = 0 |
| 视觉 | 双栏排版完整、公式/引用正常、无重叠缺字；瑕疵：作者区邮箱断行（拆段生硬） |
| 测试 | 22/22 passed |

## 观察

1. flash-low 对占位符协议的遵从度在此规模下完美（此前担心的主要风险未出现）；
   需更大 sheet（>300 段）复测违规率，protocol_report.py 可离线回放。
2. 翻译质量本身可用：标题、摘要术语正确（联邦学习/投毒攻击/后门）。
3. `page` 字段 0-based；`abandon` 标签在 native 模式下不跳过（与原管道一致，因为
   should_skip_translate_layout_label 仅在 mineru_doclayout_enabled 时生效）。
4. 工具层修复记录：progress monitor 需用 get_translation_stage 全表；
   doc_layout_model 需显式 DocLayoutModel.load_available()；
   fix_media_box 不幂等，mediabox_data 必须 extract 时捕获入 state.pkl；
   output_dir 需 mkdir。

## 结论

MVP（extract→subagent 翻译→apply→reconstruct→render→验证）全链路成立。
下一步：M3 agy 全自主编排实验（SKILL.md 已就位）、更大 sheet 违规率测量、M4 格式杠杆。

# 实验 2：MinerU 布局 + 全文 16 页 + 严格审查 + 迭代一轮（2026-09-09）

对象：同论文全文 16 页，en→zh，`--layout mineru`（新 token，布局结果按内容哈希缓存至
`~/.cache/babeldoc/mineru-layout.v1/`）。

## MinerU label 实测分布（16 页）

title 25 / text 130 / ref_text 65 / page_number 15 / page_footnote 3 / footer 1 /
aside_text 1 / interline_equation 4 / table(12)→body 12+caption 12 /
chart(20)→body 20+caption 25 / image(1)→body 1+caption 1 / code(1)→body 1。

跳过语义（默认集）：author 13、reference 65、figure 21、table_text 12、page_number 15、
page_footnote 3、fallback_line 2、footer 1、aside_text 1、code 1 → 共 146 段保留原文渲染；
翻译 181 段（title 25 / text 118 / figure_caption 26 / table_caption 12）。
用户要求（作者区/图表内部/参考文献不译、caption 译）与默认跳过集完全吻合。

## 全文翻译与审查

- 批量：5 批 × 40 行，0 重试 0 回退，~106s（experiments/batch_translate.py）。
- 标题字号修复（extract 内小型大写双字号标题段级提升）：10 个 title 段受益，
  "I. 引言" 渲染 10.0pt（原文 9.96pt）。
- 结构化审查（review_report.py）：P0=0，title_shrink=0，double_punct=0，low_cjk=10
  （复核均为英文缩写密集的合法行）。
- 视觉审查（4 代表页 PNG）结论需谨慎：作者区"被翻译"、图 6(b) 图注"语义错误"、
  "alpha 重复句" 三项经输出 PDF 文本层复核**全部为视觉误报**；
  真问题反而藏在文本层：`{vN}` 占位符展开自带标点（如 `[17],`）+ 译文紧跟 `，`
  → 渲染成 "[17],，"（14 处）；PMR/PDR 术语 3 行用了"投毒模型率"与 13 行"毒化模型率"不一致。

## 迭代一轮（reviewer 驱动）

1. apply 增加占位符标点归一化（展开尾部带 , / . 时删除紧随的 ，/、/。）：14 处修复。
2. 术语统一（程序化改写 translated.jsonl 3 行，无需重译）：投毒模型率→毒化模型率 等。
3. 归一化回写 translated.jsonl（10 行），re-apply → reconstruct → render。
4. review_report.py 新增 P2 检查：placeholder_double_punct（target 层）、
   rendered_double_punct（输出 PDF 文本层，防止只在渲染层出现的缺陷再漏网）。
5. 复审：P0=0、P1 title_shrink=0、P2 三类全 0；全文渲染层双标点行 0（修复前 ≥14）。

## 结论与经验

1. **双轨审查必须以文本层为准**：视觉模型对作者区混排、小号图注的误报率高（本实验 3/3 误报），
   文本层（pymupdf 抽取 + 正则/join 源目）可证伪也可发现视觉发现不了的真问题。
2. 确定性缺陷（术语/标点）走程序化改写 + 重新 apply，不消耗 LLM 预算——迭代成本近乎零。
3. MinerU 布局缓存使重复 extract 免费，为 M3 全自主编排扫清成本障碍。

# 实验 3：agy 全自主编排 E2E——用户提供的 20 页论文（2026-09-09）

对象：用户提供的论文（2026-f1872，函数内联与 ML 二进制分析安全，20 页），
en→zh，`--layout mineru`，`--dual` 交付。**单次 agy 会话全自主编排**
（`gemini-3.8-flash-low --effort low`，按 SKILL.md 六阶段执行，
子代理提示词已落盘 skills/document-translate/prompts/，batch_translate.py
从该文件单一来源加载，不再内置副本）。

## 运行结果（总耗时约 7 分钟）

| 阶段 | 结果 |
|---|---|
| extract | 208 段待译；作者区/参考文献/图表内部/页眉页脚按语义跳过 |
| translate | 6 批（提示词含占位符标点协议+术语统一要求），1 重试 0 回退 |
| apply | ok=true，applied=208，violations=[]，punctuation_fixes 生效 |
| reconstruct | mono + dual（1224×792pt 拼宽，左英右中）各 20 页 |
| review | review_report + format-reviewer 清单 A-E 全 PASS（文本层证据） |
| iteration | 1 轮：agy 自主发现术语分裂并程序化统一 → re-apply → 复验 |

## 亮点：reviewer 驱动的术语统一（零 LLM 成本）

- extreme inlining：极端内联 38 / 极限内联 14 / 极致内联 6 → **极限内联 55**（变体清零）
- cost model：代价模型 9 / 成本模型 7 → **成本模型 16**
- 复核确认：在 re-apply 时由 pre_translate 注入目标术语表，而非手改全部行。

## 独立复核（ZCode 会话，非 agy 自证）

- dual 结构：20 页全部 1224×792pt，clip 抽取确认左英右中。
- 作者区/参考文献：作者姓名单位邮箱全英文；References 111 条无中文
  （唯一命中"CJK 引用行"为 p17 正文 x86 寄存器句"[rdi], rax…"，grep 误报）。
- 占位符残留 0；标题字号 22.7pt 正常；可接受渲染层双标点 2 处（p6/p12，
  占位符展开 "[47]," 后接中文逗号，属引用编号+逗号的自然混排）。
- fallback 行 LyA3N 复核：`pip install -r requirements.txt`，合法代码回退。

## 视觉走查与工具链经验

- p1/p11 渲染 PASS（标题完整、作者区英文无错位、双栏无重叠溢出豆腐块）。
- p11 视觉模型报"左栏末句与右栏首句疑似脱字"：文本层证伪——**原文 PDF 本身
  就是该句被图 10 隔断的版面**（图上方断在 "from the default"，图注后接
  "value (e.g., 225→2,225)"），译文忠实复刻。铁律再次生效（累计 4/4 视觉误报）。
- judge 子代理无法接收像素（本环境 Read PNG 只回 CDN 上传链接）→ 视觉验收
  实际依赖 analyze_image + CDN；CDN 上传服务按内容感知去重，同名/同内容文件
  会拿到**旧 URL**（本实验一度命中上一轮 FreqFed 图），需换文件名或转 JPEG
  才能得到新 key。此坑已记录，M4 前视觉通道需固化为"渲染→本地比较"为主。
- agy 启动参数顺序：所有 flag 必须放在 `--print "<prompt>"` 之前，
  否则 --print 会吞掉下一个 flag 当 prompt。
- 非交互 shell 不 source ~/.zshrc，MINERU_API_TOKEN 需启动时注入（不回显）。

## 结论

M3 达成：**输入 PDF → 单次 agy 会话 → 中英对照 PDF**，全程无人工干预；
审查-迭代闭环（含术语统一、占位符标点归一化）由编排 agent 自主完成且全部
经文本层复核。下一步 M4 格式杠杆（edit-box/碰撞检测/IR 快照）与 M5 基准评估。
