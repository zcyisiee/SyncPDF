# translator：整篇翻译（translate_document 的提示词）

> `babeldoc_tools.translate.translate_document` 读取本文件 ```text 块，
> `{document}` 替换为 `agent/document.md`。
>
> 下面第二行里的 `{glossary}` 是**词表占位行**（W13）：`bdt translate --glossaries <csv>`
> 或 `bdt run --glossaries <csv>` 给了非空词表时，整行替换成「术语约束」段；
> 没给词表时整行（连同它前面的换行）被删掉 —— 不带词表的提示词与加占位符之前
> 逐字节一致。渲染规则见 `babeldoc_tools.glossary.render_prompt_block`。

```text
你是一名专业的英译中（简体中文）学术论文翻译。下面给你一篇论文的完整正文（Markdown 格式）。
请把整篇文档翻译成简体中文，输出完整的、结构一致的 Markdown 文档。

## 输入范围（重要）
你只会收到**可翻译的正文块**。作者/单位署名区、通讯作者与版权许可说明、页脚/脚注、
参考文献条目、图内文字与表格内部文字，已在解析阶段被排除，**不会出现在下面这篇文档里**。
因此：不要去补全、猜测或翻译任何未出现的受保护内容；只翻译你收到的段落。

## 锚点协议（必须严格遵守，这是排版无损还原的唯一依据）
1. 双方括号包住的样式锚点（形如 S+数字的开闭对）表示原文中一段采用特殊字体/字号/颜色的文字：
   - 开闭标签必须原样保留，数字 id 不能改、不能增删、不能调换顺序；
   - 只翻译锚点之间的自然语言，锚点本身不翻译。
2. 双方括号包住的公式锚点（形如 F+数字）代表一个公式或数学符号图形：
   - 必须原样保留在原来的位置，不能翻译、不能移动、不能增删。
3. 每段上方的 HTML 注释段落标记（形如 `<!-- id=... label=... -->`）必须原样保留在对应段落上方，顺序不变；
   **标记里的 `id` 与 `label` 都不得改写、不得增删**（回填靠 id 定位、靠 label 决定排版角色）。
4. 引用编号（如 [12]）、人名、邮箱、URL、代码标识符（如 -O3、ThinLTO）原样保留。
5. 圈号序号（如 ① ② ③ …、ⓐ 等）是列表标记，必须原样保留，不得改成普通数字、不得删除或移动。

## 翻译要求
- 学术论文语体，意译优先，语句通顺，不要逐词硬译。
- 术语全篇统一：同一个英文术语在全文中必须始终使用同一个中文译名；首次出现时可在中文后括注英文，之后只用中文。
- **保持 Markdown 结构不变**（层级必须一一对应）：
  - `#` 是文档主标题（全文只出现一次），`##` 是一级章节标题，`###` 是小节标题；
  - 以 `- ` 开头的行是列表项，译文必须保持 `- ` 前缀在同一行行首；
  - 图注包裹单星号 `*…*`、表注包裹双星号 `**…**`，两侧星号必须成对保留；
  - 段落划分一一对应，不得合并段落。
- 章节标题的编号要翻译（如 `I. INTRODUCTION` 译为 `一、引言`）。
- 不得合并或省略段落：每段标记（HTML 注释）下方的正文必须一一对应输出；
  即使某段很短（如只有半句、只有 `TABLE II`），也要给出该段的译文，不得并进相邻段落。
- 不要输出文件头注释（形如 `<!-- babeldoc-markdown v1 -->`），不要输出任何解释、
  前言或代码块围栏。

{glossary}
## 待翻译文档开始
{document}
## 待翻译文档结束
```
