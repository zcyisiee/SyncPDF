# 在线翻译部署设计

状态：**目标与待决策项，尚非部署方案**。当前实现见根目录 `ARCHITECTURE.md` 和 [管线参考](../reference/pipeline.md)。本轮只建立文档，不修改产品架构，不锁定数据库或资产存储后端。

## 已确认目标

用户上传 PDF，能持续看到真实翻译进度；对不满意的段落快速修改或重译，预览局部排版，再导出对应修订。云服务器磁盘有限，系统必须有明确的数据责任和生命周期，避免每次翻译、预览、版本归档都无限复制文件。

当前已具备单机工作台、SQLite 元数据、本地哈希资产、SSE、草稿 revision、局部编译与导出。在线演进要沿用这些边界，并验证它们在目标部署规模下是否够用。多租户、水平扩展、协同编辑、WebSocket 和独立队列均未被确定为本期必需能力。

## 目标执行边界

```text
用户上传 / 编辑 → 服务接入与权限范围 → 任务调度 → 解析 / 翻译 / 编译
                         ↓                   ↓
                    元数据与修订         可恢复产物与进度事件
                         └────── 预览 / 当前修订导出 ──────→ 用户
```

这是责任划分，不意味着每个框都要成为独立服务。外部操作仍通过 `bdt` 子命令或参数暴露，不能另建 worker CLI。

| 用户动作 | 目标验收条件 | 当前需要补齐或验证 |
|---|---|---|
| 上传 | 成功后身份/源文件可恢复；空间不足有明确错误 | 已有大小限制与去重；需磁盘预算、失败残留及权限范围验证 |
| 追踪翻译 | 重连能恢复状态；取消和失败不会显示成功 | 已有持久 SSE；需断网、进程退出、事件保留期限验收 |
| 修改段落 | 保存与编译分离；旧结果不覆盖新 revision | 已有 revision 检查；需真实论文样本的局部重排耗时与质量基线 |
| 导出 | 明确导出的 revision；最新失败时仍能识别旧版 | 两套编译/导出机制并存；需统一用户语义与恢复用例 |
| 长期运行 | 峰值磁盘可估算，回收不会损坏可恢复任务 | 现有清理只处理有限目录；缺完整资产引用与保留策略 |

## 数据库与磁盘是两个问题

数据库负责文档身份、修订、任务、事件、资产引用与一致性；PDF、解析快照、页面图、编译缓存仍占文件或对象空间。引入数据库本身不会缩小这些二进制产物。选型前应统计一份代表性 PDF 在解析、翻译、局部预览、全量编译、归档各阶段的磁盘峰值与重复副本。

| 数据类别 | 必须满足的约束 | 回收前提（待实现/验证） |
|---|---|---|
| 原 PDF 与最新人工修改 | 可恢复、可追溯所属文档和 revision | 用户删除或明确到期策略；不能随缓存清理丢失 |
| 解析状态、锚点、修复 PDF | 重编译能找到完整且相容的输入 | 验证可重建性、记录解析器版本后再考虑淘汰；不能把 `state.pkl` 当跨版本永久格式 |
| 成品及历史版本 | 区分当前、旧版与失败尝试，下载与元数据一致 | 确定保留份数/期限与用户预期 |
| 页面预览、字体/渲染缓存 | 命中键包含必要输入，可按需重建 | 无活动任务引用，且不会失去唯一可下载版本 |
| 任务事件与诊断 | 支持失败分析、重连与状态恢复 | 分别确定持久事件与详细 debug 的保留窗口 |
| 临时隔离目录 | 有归属和任务结束状态 | 任务退出/取消并释放引用后清理；重启可辨认孤儿目录 |

元数据删除与资产删除需要可恢复顺序，不能数据库先宣称成功而文件尚未发布。按内容哈希去重也需要文档归属与引用检查，不能让共享资产被一个文档删除动作误删。源文件、数据库、兼容文件的备份/恢复边界要在移除旧存储前验证。

## 候选方案（未选定）

元数据与资产位置应分别决策，不把“换数据库”和“上对象存储”绑定为一次重构。

| 维度 | 候选 | 适用条件与代价 |
|---|---|---|
| 元数据 | 延续 SQLite | 单机部署简单；需验证写并发、WAL 增长、备份恢复与单进程调度边界 |
| 元数据 | 独立关系型数据库（如 PostgreSQL） | 多实例一致性、并发写等需求明确后评估；增加服务维护与迁移成本 |
| 大文件 | 延续本地文件资产 | 单机读写简单；必须有容量预算、去重和回收，容量仍受云盘限制 |
| 大文件 | 对象存储（如 S3 兼容服务、OSS） | 可把长期文件移出计算节点；需验证 Range、上传/下载成本、访问控制、本地热缓存与失败重试 |
| 调度 | 延续进程内队列 | 部署简单；进程重启和多副本任务准入需明确 |
| 调度 | 持久任务队列或数据库任务表驱动 | 恢复/多实例需求明确再引入；幂等、租约、取消、重复投递均需验收 |

以上是评估维度，不代表已有适配器或性能结论。具体产品/API 能力应在选型时以官方文档与实测确认。

## 实施前的决策与检查出口

1. 明确首期部署人数、同时翻译数、机器内存/磁盘上限、典型 PDF 大小，以及能接受的等待时间。
2. 定义必须保留的数据、历史版本期限、失败诊断期限、备份恢复目标；不能默认永久保留全部中间产物。
3. 先测当前 SQLite + 文件方案的单文档磁盘峰值、局部编译延迟、取消/重启恢复，再比较候选成本。
4. 决定受控单用户还是多用户服务；若向多人开放，需要明确认证、文档授权、模型凭证与任务资源隔离。
5. 确定两套事件/编译/存储接口的迁移顺序，用旧 workdir、断线、过期 revision、磁盘不足、崩溃恢复和重复上传用例验收。
