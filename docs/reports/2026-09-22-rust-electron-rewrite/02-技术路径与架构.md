# SyncPDF 技术路径与架构

日期：2026-09-22。本文是实施时的设计基准。每一节都对应 `03-整体计划与任务拆分.md` 中的任务。

---

## 1. 总体架构

```
┌──────────────────────── Electron app (syncpdf) ────────────────────────┐
│ renderer (React + VSCode 视觉系统)                                      │
│   活动栏 │ 侧栏(文档/段落树) │ 编辑器区(源 PDF | 译文 PDF | 段落编辑) │ 面板 │
│         ▲ contextBridge 白名单 (ipc) / MessagePort (高频事件)           │
│ preload                                                                 │
│ main: 窗口、协议 handler(syncpdf-file://)、sidecar 生命周期、凭据存储   │
└──────────────┬──────────────────────────────────────────────────────────┘
               │ child_process.spawn   stdin: 请求 JSONL   stdout: 事件 JSONL
┌──────────────▼──────────────── Rust 引擎 (syncpdf-cli sidecar) ─────────┐
│ pdf(解析/回写) → layout(ONNX) → paragraph → translate(LLM+校验+缓存)     │
│   → typeset(塑形/断行/fit) → writeback(补丁+隔离流+字体) → validate      │
│ 存储: ~/Library/Application Support/SyncPDF/{db,cache,models,fonts}      │
└─────────────────────────────────────────────────────────────────────────┘
```

两个进程，一条 JSONL 管道。引擎独立可用（CLI），不依赖 Electron。

## 3. 数据流与阶段

| 阶段（JSONL stage 名） | 输入 | 输出 | 缓存键 |
|---|---|---|---|
| preflight | PDF 路径 | 页数、加密 / 签名检测、字体清单 | 文件 sha256 |
| source_analysis | PDF | 每页 `PageIR`（DisplayItem + Glyph） | 文件 sha256 + 页号 + 解析器版本 |
| layout_analysis | 页位图（pdfium 渲染，150dpi）| 区域框 + 类别 + 阅读顺序；覆盖率门禁 | 页 IR 哈希 + 模型 id |
| paragraph_analysis | PageIR + 区域 | `Paragraph[]`（含 char id 集合、样式 run、原子）| 上游哈希 |
| translating | Paragraph → TranslationUnit | 译文 HTML + 校验结果 | `(src_lang, tgt_lang, sha256(source_html))` |
| typesetting | 译文 + 段落框 + 字体 | `LineBox[]`（逐字形位置、字号、缩放） | 上游哈希 + 字体 profile |
| validating | 补丁 + 生成流 | 自校验报告 | — |
| publishing | 原 PDF + 补丁 + 新流 + 字体 | 输出 PDF（原子落盘） | — |

每阶段输入哈希写入 `run_state`，续跑时校验（对应规约 #4）。stage 序列与 hjfy 一致，便于事件语义复用。

## 4. IR 设计

### 4.1 稳定标识

| 类型 | 形式 | 说明 |
|---|---|---|
| `PageId` | `u32` 页索引（0 基） | — |
| `OpKey` | `(stream_obj: (u32,u16), op_index: u32)` | 与 hjfy 补丁键一致；Form XObject 内的 op 用 XObject 自身流的 obj id |
| `GlyphId` | `(PageId, OpKey, glyph_ordinal: u16)` | 显式、可序列化；取代 Python `id()` |
| `ParagraphId` | `P{page:02}-{seq:03}`，字符串 | 与现版协议一致，模型可见 |
| `AtomId` | `{{KEEP_n}}` 段内序号 | 公式 / 不可译片段 |
| `StyleId` | `data-style="n"` 段内序号 | 样式 run |

所有跨阶段引用只用上述 id。禁止在 IR 之间持有指针或引用。

### 4.2 Glyph（源字形）

```rust
struct Glyph {
    id: GlyphId,
    unicode: SmallVec<[char; 2]>,     // 解码文本，可能为空（无 ToUnicode）
    code: u32,                        // 原始编码值
    font: FontRef,                    // 页资源中字体键 + 解析后描述
    size: f32, matrix: [f32; 6],      // 含 CTM 的最终文本矩阵
    bbox: Rect,                       // PDF 用户空间，左下原点
    advance: f32,
    fill: Color, render_mode: u8,
    source: GlyphSource,              // { element_index, string_operand_range, decoded_code_range }
    flags: GlyphFlags,                // 空白、Type3、隐藏(Tr 3/7)、裁剪外
}
```

`GlyphSource` 照搬 hjfy 三元组。它决定回写时能否删除该字形所在的 text-show 操作。

### 4.3 DisplayItem

`Text(Vec<Glyph>)` / `Image { obj, bbox }` / `InlineImage` / `Path { bbox, is_fill, is_stroke }` / `FormBegin { xobject, ctm }` / `FormEnd`。图像与路径只记几何，回写时不动。

### 4.4 Paragraph

```rust
struct Paragraph {
    id: ParagraphId,
    page: PageId,
    region: RegionRef,                // 布局框 + 类别（text/title/list/caption/table/formula/...）
    lines: Vec<Line>,                 // 每行 glyph id 列表、基线、行距
    style_runs: Vec<StyleRun>,        // { style_id, glyph_range, font, size, color, bold/italic }
    atoms: Vec<Atom>,                 // { atom_id, glyph_range, kind: Formula|Code|Url|Number|Symbol }
    source_html: String,              // 生成的翻译单元源文本
    alignment: Align, first_indent: f32, is_rtl: bool,
    translatable: Translatable,       // Yes | No(reason)  → not_replaced 落定语义（规约 #9）
}
```

### 4.5 链接与注记

`LinkAnchor { annot_obj, rect, glyph_ids: Vec<GlyphId>, paragraph: Option<ParagraphId> }`。四级定位保留：stamp（注记本身） → char_union（glyph_ids 并集）→ anchor（段内相对位置）→ paragraph。回写只改 `/Rect`，动作与 Border 保留。审计五分类照现版。

### 4.6 序列化

所有 IR 用 serde。磁盘缓存 CBOR + zstd 存 SQLite BLOB。调试导出 JSON。不再有 pickle / XML。

## 5. 翻译协议

### 5.1 翻译单元格式

采用 hjfy 受限 HTML，并入现版锚点语义：

```html
<p id="P01-003">Deep <span data-style="1">learning</span> models {{KEEP_1}} achieve …</p>
```

| 元素 | 规则 |
|---|---|
| `<p id>` | 段落身份；模型不得改动、不得重编号 |
| `<span data-style="n">` | 样式 run；数量必须一一对应，顺序自由 |
| `{{KEEP_n}}` | 原子（公式、代码、URL、编号等）；多重集必须相等 |
| `<br>` | 硬换行（诗歌、地址）；数量相等 |

允许标签白名单只有以上四种。其余标签 = invalid_markup。

### 5.2 请求组装

每次请求含：系统提示词（目标语言、格式规则）、`TERMINOLOGY`（可选术语表）、`CONTEXT_BEFORE` / `CONTEXT_AFTER`（相邻段纯文本，不可译出）、`ATOM_HINTS`（原子的可读描述）、正文（一批 `<p>`）。批大小按字符数上限（默认 6000）与段数上限（默认 20）取小。

### 5.3 校验错误码（16 条，来自 hjfy，全部实现）

| 码 | 触发 | 处置 |
|---|---|---|
| invalid_markup | 非法标签 / 未闭合 | 拆分重试 |
| placeholder_count | `{{KEEP}}` 多重集不等 | 拆分重试 |
| unknown_placeholder | 出现源文没有的占位 | 拆分重试 |
| atom_hint_leakage | ATOM_HINTS 文本进入译文 | 拆分重试 |
| link_label_changed | 链接标签文本被改 | 拆分重试 |
| style_count | span 数不等 | 拆分重试 |
| unknown_style | 未知 data-style | 拆分重试 |
| empty_style | 空 span | 拆分重试 |
| unsafe_bidi_control | 含 U+202A–202E 等 | 拆分重试 |
| unbalanced_bidi_isolate | FSI/LRI/RLI 不配对 | 拆分重试 |
| duplicated_text_slots | 同一 id 出现两次 | 拆分重试 |
| neighbor_context_leakage | CONTEXT 文本进入译文 | 拆分重试 |
| pathological_text_repetition | 重复 n-gram 超阈值 | 拆分重试 |
| protected_literal_count | 数字 / 单位等受保护字面量数量变化 | 警告或重试（可配） |
| excessive_target_expansion | 译文 / 原文长度比超阈值（默认 3.0） | 拆分重试 |
| insufficient_target_language | 目标语言字符占比过低 | 拆分重试 |
| residual_japanese | 目标非日文却残留假名 | 拆分重试 |

现版规约 #1/#2/#3 映射：多 id → `duplicated_text_slots` 或 `unknown_paragraph`（新增第 17 码，段外 id）；漏 id → 拆分后仍失败即回退原文并记 `fallback_ids`；空译记 `empty_ids`。回退通过 `issue` 事件与最终报告可见。

### 5.4 拆分重试

批失败 → 按段二分 → 单段失败 → 按 span / 原子边界二分 → 仍失败则该段 `fallback`。最大重试次数默认 3。每次失败发 `issue` 事件。

### 5.5 缓存

```sql
CREATE TABLE translations(
  source_language TEXT NOT NULL, target_language TEXT NOT NULL,
  source_hash BLOB NOT NULL,            -- sha256(source_html)，32 字节
  origin TEXT NOT NULL,                 -- provider/model
  source_html TEXT NOT NULL, translated_html TEXT NOT NULL,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY(source_language, target_language, source_hash)
) WITHOUT ROWID;
PRAGMA journal_mode=WAL;
```

命中即跳过 LLM。用户手动编辑的译文写回同表并标 `origin='manual'`，优先级最高。

### 5.6 LLM 客户端

genai 0.6.5 统一接口。默认提供方 OpenAI 兼容端点（base_url + model），第二为 Anthropic Messages。并发上限由 tokio Semaphore 控制，初始 4，按 `x-ratelimit-remaining-*` / 429 `retry-after` 自适应。流式（SSE）用于逐段更新事件；非流式用于批。API key 从主进程经 stdin 首条 `configure` 消息传入，不进 argv，不进日志。

## 6. 回写算法（核心）

### 6.1 总体

```
输入: 原 PDF, 每页 { 待删 GlyphId 集合, 译文 LineBox[], 需要的字体 }
1. 对每页每条内容流（含递归到的 Form XObject）解析为 Op[]，带 OpKey
2. 对每个 text-show Op（Tj/TJ/'/"）：
     命中集 = 该 Op 产出的 glyph ∩ 待删集合
     全部命中 → 删除该 Op；若其前置 Tf/Tm/Td/Tc/Tw/Tz/Ts/rg 之后没有其他消费者，一并删除
     部分命中 → 保留整条 Op（原子 / 不可译片段原地留下）
     零命中 → 保留
3. Form XObject：若其内部有待删 Op，克隆该 XObject（新 obj id），对克隆体打补丁，
   页资源中改名引用克隆体；原 XObject 不动（其他页可能共享）
4. 生成译文流：
     "q\n" + 每段 { 遮挡矩形(可选) + BT … 逐字形 Tm+Tj … ET } + "\nQ\n"
   ActualText 包裹多样式行 / RTL 行
5. 页 /Contents 改为数组 [ "q" 流, 原各流(已补丁), "Q" + 译文流 ]
6. 页资源 /Font 加入 SPF{n}（不与已有名冲突）；ExtGState SPGS 用于透明度
7. 序列化：pdf-writer 写新对象；未改动对象按原字节透传（增量更新或全量重写，见 6.4）
8. 写 <out>.tmp.pdf → 自校验 → 可选 qpdf --check → rename
```

### 6.2 Op 过滤器

参考 pdf-rs `Op` 枚举自写 lexer/parser，支持全部 PDF 2.0 内容流操作符与内联图像（BI…ID…EI）。解析器记录每个 Op 的字节范围，未改动 Op 直接拷贝原字节，不重新序列化。这保证「不动的部分字节级不变」。

### 6.3 安全自检（发布前必过）

| 检查 | 失败处置 |
|---|---|
| PartialTextOperation：删了部分命中的 Op | 整页回退不译 |
| UnknownSelectedGlyph：待删 glyph 找不到 Op | 整页回退 |
| PreservedGlyphChanged：保留字形位置变化 | 整页回退 |
| GraphicsStateUnderflow：生成流 q/Q 不平衡 | 构建失败 |
| InvalidGeneratedCid：CID 不在子集内 | 构建失败 |
| PageContentsMismatch：原流哈希与解析时不同 | 构建失败 |
| DigitalSignaturesRemain：文档含签名 | 拒绝处理，发 issue |
| Encrypted：加密文档 | 拒绝处理（首发） |
| LinkRectDrift：链接矩形移出段落框 | 记审计，不阻塞 |

### 6.4 序列化策略

首发用**全量重写**（lopdf 0.45 读对象树 → 修改 → 保存），简单可靠。导出膨胀目标 <2×，靠不重复嵌入字体与对象流压缩达成。增量更新（append xref）列为 M4 可选优化。

### 6.5 双语模式

同一算法，译文段落写在拼宽后的新页右半，源页内容通过 Form XObject 引用放左半。链接 / 书签搬运。M4 实施。

## 7. 字体嵌入

| 项 | 方案 |
|---|---|
| 来源 | 内置字体包：Noto Sans CJK / Noto Serif CJK（ttc，face 0 JP / 1 KR / 2 SC / 3 TC）、Inter、PT Serif、Noto Sans Arabic；fontdb 也扫描系统字体作回退 |
| 角色链 | profile `body / doc_title / paragraph_title / mono / raster`，每角色 regular/bold/italic/bold-italic 四变体；缺变体用 `italic_shear`（斜体）或 `Tr 2` 描边（伪粗） |
| 匹配 | 源字体 flags（serif / fixed / italic / weight）→ 角色 → 目标语言脚本 → 具体 face |
| 嵌入类型 | `/Type0` + `/CIDFontType2`；有 `CFF ` 表用 `/FontFile3 /OpenType`，否则 `/FontFile2` |
| 子集 | subsetter 0.2.6，保持 gid；每文档每 face 一个子集，收集全部用到的 gid 后一次生成 |
| CMap | 自定义 `/SPFEncoding`：codespace `<0000>–<FFFF>`，`cidchar` 逐 code→cid；cid = gid；`/CIDToGIDMap /Identity` |
| 宽度 | `/DW 1000` + `/W` 数组（skrifa advance × 1000 / upem） |
| ToUnicode | `bfchar` / `bfrange`，多码点字形用 UTF-16BE 串 |
| FontDescriptor | Flags / ItalicAngle / Ascent / Descent / CapHeight / StemV 由 skrifa 读 OS/2 + hhea + post |
| 资源名 | `SPF{n}`，扫描页现有 `/Font` 键避免冲突 |

## 8. 排版与溢出策略

### 8.1 输入输出

输入：译文 HTML（已校验）、段落框、原段落样式（字号、行距、对齐、首行缩进）、字体 profile。输出：`LineBox[]`，每行含逐字形 `(gid, x, y, size, scale_x, style)`。

### 8.2 流程

1. HTML → 逻辑文本 + 样式 run + 原子（原子以原字形几何占位，不塑形）。
2. unicode-bidi 重排；按 script 分段 harfrust 塑形。
3. icu_segmenter LineSegmenter Strict 求断点；西文单词内加 hypher 软断点（仅当无断点可用时启用）。
4. fit 阶梯：字号 scale ∈ {1.0, 0.95, 0.9, …, min_scale(默认 0.6)} × 行距 ∈ {原, 0.95, 0.9}；首个能容纳的档位胜出。快路与逐档必须同结果（规约 #10）：只有一种实现。
5. 仍溢出：邻接间隙加宽（同列上下相邻文本区域，垂直中心差 ≤6pt，加宽上限 = 间隙），裁剪到障碍（图像 / 路径 bbox）。
6. 仍溢出：允许向下溢出到段落框下沿 + 最多 1 行高，碰撞检测其他区域；碰撞则回到最小档位并发 `issue{code: overflow}`。
7. 对齐：两端对齐通过词间距分配；CJK 段用字距均分；末行左对齐。

### 8.3 首发不做

竖排、首字下沉、位图页 OCR + inpainting、表格内翻译（表格作为原子整体保留）。以上列入 M4 之后。

## 9. JSONL 协议

### 9.1 传输

主进程 spawn `syncpdf-cli run --protocol 1`。stdin 每行一个请求对象；stdout 每行一个事件对象；stderr 为 tracing 日志（人读）。stdin EOF 或 `{"type":"cancel"}` = 取消，引擎 5s 内收尾退出；超时主进程 kill。

### 9.2 请求

| type | 字段 | 说明 |
|---|---|---|
| configure | provider, base_url, model, api_key, concurrency, cache_dir | 首条；api_key 只在此出现 |
| run | doc_id, input, output, source_lang, target_lang, pages?, font_profile?, terminology?, mode: full \| bilingual | 启动任务 |
| retranslate | doc_id, paragraph_ids[] | 局部重译 |
| apply_edit | doc_id, paragraph_id, translated_html, base_revision | 手动编辑 → 重排版 + 局部回写 |
| export | doc_id, output, mode | 发布 |
| cancel | — | 取消当前任务 |

### 9.3 事件

```json
{"seq":123,"ts":1727000000.123,"type":"progress","stage":"translating","done":42,"total":169}
```

| type | 说明 |
|---|---|
| run_started | protocol_version, engine_version, doc_id, pages |
| stage_started / stage_finished | stage 名 + 耗时 |
| progress | stage, done, total；不编造 ETA |
| paragraph | paragraph_id, status: translated \| typeset \| not_replaced \| fallback, boxes (PDF 坐标, coord_system 字段), translated_html |
| page_ready | page, preview_path（可选增量预览 PDF） |
| issue | severity, code, paragraph_id?, page?, message |
| document_finished | output, stats（字体数、膨胀比、fallback 数） |
| run_finished | ok, elapsed |
| error | fatal, code, message |

`seq` 单调递增。前端断线后用 `seq` 续传（引擎在 store 中保留当前 run 的事件日志）。段落框为 `null` 表示未识别，`[]` 表示识别了但无框（规约 #12/#13）。

## 10. 存储布局

```
~/Library/Application Support/SyncPDF/
  app.db                     # rusqlite；documents, runs, run_events, drafts(revision), paragraphs, assets
  cache/
    translations.db          # 翻译缓存（独立库，可清空）
    stages/<sha256>/          # 阶段产物 CBOR+zstd（可清空）
  assets/<sha256[0:2]>/<sha256>   # 内容寻址：源 PDF、输出 PDF、预览
  models/                    # PP-DocLayoutV2.onnx, PP-OCRv6*.onnx + manifest.json(sha256)
  fonts/                     # 内置字体（随应用分发，此处为用户追加）
  credentials.json           # 0600；主进程读写；引擎不读此文件
  logs/
```

草稿 revision 单调 +1，`apply_edit` 带 `base_revision`，不匹配返回 `error{code: conflict}`（规约 #5）。资产删除只删引用，共享资产按引用计数回收（规约 #14）。

## 11. 安全规则

| 规则 | 实现 |
|---|---|
| API key 不进 argv | 只通过 stdin `configure` 传入 |
| API key 不进日志 | tracing 层对 `configure` 事件做脱敏；`Debug` impl 打码 |
| 凭据文件 0600 | 主进程用 `fs.writeFile(path, data, {mode: 0o600})`；macOS 后续可迁 Keychain |
| 引擎不信任环境代理 | reqwest 显式配置，不读 `HTTP_PROXY`（除非用户设置） |
| 渲染进程零 Node | `contextIsolation: true, nodeIntegration: false, sandbox: true` |
| 本地文件访问 | 只通过 `syncpdf-file://` 协议 handler，白名单目录 |
| 输入 PDF 视为不可信 | 解析在 sidecar 内；崩溃只影响 sidecar，主进程重启它 |

## 12. Electron 应用结构

### 12.1 VSCode 部件映射

| VSCode 部件 | SyncPDF 内容 | 实现 |
|---|---|---|
| 标题栏 | 文档名、运行状态 | 自绘（`titleBarStyle: hiddenInset`） |
| 活动栏 | 文档 / 段落 / 术语 / 设置 | codicons + `--vscode-activityBar-*` |
| 侧栏 | 段落树（页 → 段落，状态图标）、文档列表 | @vscode-elements tree |
| 编辑器区 | 三栏：源 PDF 预览 / 译文 PDF 预览 / 段落编辑器 | allotment 分栏；pdfjs 裸 API |
| 面板 | 问题（issue 列表）、输出（引擎日志）、终端（无） | allotment 底栏 |
| 状态栏 | 阶段、进度、模型、缓存命中率 | `--vscode-statusBar-*` |

主题：把 VSCode Dark Modern / Light Modern 的 token 表导出为 CSS 变量，跟随系统。

### 12.2 渲染进程状态

Zustand 两个 store 沿用现版划分：`documentStore`（文档、段落、事件流）与 `uiStore`（布局、选中、面板）。TanStack Query 不再需要（无 HTTP），改为 IPC 事件驱动。

### 12.3 PDF 预览

pdfjs-dist 6.3.289，`?worker` 引入 module worker；文件经 `syncpdf-file://` 读取；HiDPI 用 `setTransform`。段落框叠层用 `viewport.convertToViewportRectangle`，这是前端唯一坐标换算点（规约 #6）。源与译两个 viewer 滚动同步、页同步。

### 12.4 段落编辑器

普通 textarea + 受限 HTML 高亮（span / KEEP 作为不可编辑 chip）。保存 → `apply_edit` → 引擎重排版该段 → `paragraph` 事件 → 局部预览刷新。目标 <200ms。

## 13. IPC 设计

```
renderer ──(window.syncpdf.startRun(req))──▶ preload ──ipcRenderer.invoke('engine:run')──▶ main
main ──child.stdin.write(JSONL)──▶ sidecar
sidecar ──stdout JSONL──▶ main ──(低频) webContents.send('engine:event') / (高频) MessagePort──▶ renderer
```

contextBridge 白名单（只暴露这些）：`configure`, `startRun`, `retranslate`, `applyEdit`, `exportDocument`, `cancel`, `onEvent`, `openFile`, `readCredentials`, `writeCredentials`。

主进程职责：spawn / 重启 sidecar、请求 id 关联、stdin 写入序列化、按行解析 stdout、崩溃时发 `error{fatal}` 并重启、退出时 EOF + 5s 后 kill。

## 14. 并发模型

| 资源 | 策略 |
|---|---|
| pdfium | 专用单线程 + mpsc 队列；所有解析 / 渲染请求排队 |
| ort | 每模型一个 session；page 并行时 intra-op 线程 1–2；总线程 ≤ 物理核 |
| 排版 | rayon 池，按段落并行；纯 CPU |
| LLM | tokio；Semaphore 自适应 |
| 回写 | 按页并行生成流；序列化单线程 |
| 事件 | 单 mpsc → stdout 写线程；seq 在写线程分配 |

规则：tokio worker 内不做 CPU 密集工作，用 `spawn_blocking` 或投给 rayon。

## 15. 降级与错误

| 情况 | 行为 |
|---|---|
| 布局模型缺失 | 发 issue，用启发式行聚类分段（质量低但可用） |
| 字体缺失 | 回退 Noto Sans；issue |
| 页含签名 / 加密 | 该文档拒绝；issue fatal |
| 页解析失败 | 该页 not_replaced；继续 |
| 段落校验失败到底 | fallback 原文；issue |
| LLM 不可达 | 任务失败，已缓存段保留；可续跑 |
| 自校验失败 | 该页回退不译，重新生成；二次失败任务失败 |

任务不因单页单段失败而失败（规约 #17）。
