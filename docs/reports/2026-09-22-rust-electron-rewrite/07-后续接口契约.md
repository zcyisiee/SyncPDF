# 后续后端接口契约

2026-09-22，主控依据完整用户目标和只读代码审计冻结。本文是实施合同，**不是现有能力说明**；是否实现及验收结果只看唯一 [task-state](task-state.md)。R1整体验收后才启动下一批实现。

## R2：源文本与发布一致性

### 源文本

- `Paragraph.glyphs` 仍是源操作身份，索引只指向真实源字形，不插入虚构空格字形。
- 新增 `SourceTextSpan { text: String, glyph_range: (u32, u32) }` 和带serde默认值的 `Paragraph.text_spans`。范围采用段内字形索引，半开；零长度范围表示该边界生成的空格/换行。文本、样式和原子识别共同消费这份阅读序映射。
- `Paragraph.text` 是逻辑源文；`build_unit` 优先消费非空 `text_spans`，旧无映射夹具保留兼容路径。不能修了段落文本却继续把缺空格的glyph串送入模型。
- 合成空格必须有字形间几何间隙或行间连接证据；保留显式空格、连字、组合字符，不能把标点和连续CJK强制分隔。行末连字符不得无条件删除并改变词义。
- 不跨栏拼段；同一源字形不能被重叠区域重复分配。旋转侧注保留源绘制，不能按普通水平行产生乱码。
- `FootNote` 不译。作者/地址优先结合首页标题、摘要/正文边界及邮箱/机构线索保护；无法可靠判定时记录依据，不把普通正文泛化为作者信息。图片、代码、reference维持源绘制。

### 发布与状态（主控独占）

- `typeset_by_page` 可含已准备但页尚未完成的块；写快照必须显式筛选“已提交页 + 当前候选页”。页内段按稳定ID排序。
- 删除与渲染在私有候选文档执行；成功原子保存后才替换主文档、递增revision、发PageReady。失败时文档、已有输出和revision保持，不吞错误。
- 已落定段落的重复交付幂等；未知ID拒绝。失败、取消、缺绑定和校验失败传播到RunFinished及CLI退出码。
- 自检的目标文字预期来自实际替换内容，不能要求reference页或全回退页出现中文。结构/字体/链接自检错误阻止完整成功事件。
- 默认保持源或用户字号。不能容纳的段明确提示并保留原文；不得进入删除集合。后续编辑编译同样执行，草稿与成功发布revision分开。

## Markdown one-shot 传输

- 保留结构化 `ParsedUnit/Segment` 作为排版输入。Markdown是模型输入输出，HTML仅作为迁移期间内部兼容格式，不作为新模型提示词要求。
- 使用独立版本化Markdown模块。块由独占行 `<!-- syncpdf:block P01-001 -->` 和 `<!-- syncpdf:end P01-001 -->` 显式闭合；结束ID须匹配。
- 段内样式用扩展Markdown `[文字]{style=1}`，原子用 `{{KEEP_1}}`；硬换行用反斜杠行末。所有源样式/原子身份须保留并校验。保留文字中的Markdown符号通过反斜杠转义，不从模型新造的粗斜符号推断源字体。
- 后续链接使用 `[文字]{link=1}`，可包含样式节点；链接目的地只存在后端，模型只保留身份。未接链接前不能宣称已支持。
- 增量解析以结束标记闭合立即交付，任意UTF-8字符边界分片结果相同；半块、重复ID、未知标记、身份丢失、尾部通道失败均可定位。
- 整份文档一个主请求，默认不按页切片；调用方显式容量上限超出时返回明确错误。补救重试与主请求分别统计，不伪装成一次调用。缓存键包含传输版本。

## 后续排版与PDF合同

- `ShapedGlyph` 必须携带实际fallback字体身份与cluster跨度；一个cluster不可被断行切开。样式逐run保留字号/颜色/源字体角色，稳定字体ID只是前置条件。
- Knuth–Plass算法用box/glue/penalty和段级badness/fitness选择断点，普通正文两端对齐、末行左对齐，标题保留源对齐。禁止通过字号阶梯规避容纳失败。
- 原子必须有源几何/绘制身份和目标位置。在可靠保留或移动源绘制前，包含原子的段不能删除全部源字形后只画占位宽度。
- 链接按源span身份重建译文Rect/QuadPoints，URI/GoTo/命名目标保持；目录和outline要保存层级及目的地并翻译标题。
- dual每页A3横向（420×297mm）；左右各半页，分别按CropBox/Rotate等比例居中适配原文与当前译文，不裁内容。两侧注释与内部目的地使用对应变换。
- 编辑请求以源SHA、block ID、base revision定位，提供字体与字号覆盖、可选译文。成功重编译从不可变源基线生成当前revision；过期revision和无效字号拒绝，重启恢复同一草稿/产物。

共享core IR、protocol、主run及跨模块接线由主控维护；叶子只修改brief授权文件。每次接口变更同时更新调用者和必要的行为守卫，不用编译通过代替真实PDF验收。

## R3 当前冻结接口（实施中）

- `StyleRun.size`保留源精确pt，不按0.5pt量化；新增带serde默认的`serif/mono`源字体角色。`Paragraph.line_height`始终为源基线步长pt，转换为`ParagraphSpec.line_height`的字号倍数仅在pipeline适配处进行。
- `StyleSpec`保留原粗斜/mono/script字段，新增`serif`、可选`size/color/font`；size为指定run的绝对pt，None才继承段落。`PlacedGlyph.color: Option<Color>`携带逐run颜色，旧IR缺失时继承段落颜色。编辑font覆盖后续须先确认字体ID有效。
- font crate `ShapedGlyph.cluster_end`和typeset适配后的范围都按当前完整输入字符串的UTF8字节半开区间；同簇字形共享范围。`shape_runs_directional`接收logical方向run，上层不得先按字符reverse。真实fallback字体身份贯穿到PlacedGlyph。
- 纯`knuth_plass`模块输出Node范围及所选break_at/ratio；调用者负责cluster→Box、空格/CJK间距→Glue、普通/强制/连字→Penalty。模块只改变Glue，不改变Box宽度和字号；不可行显式失败。冻结API及严密边界在`codex-r3-knuth/tmp/backend-repair/brief.md`；实际接入与质量仍待主控验收。
