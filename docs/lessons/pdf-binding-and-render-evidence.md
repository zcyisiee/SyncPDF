# PDF 绑定与渲染必须分别举证

本条提炼已完成的绑定审查和真实渲染失败证据；整个 Rust 后端质量任务仍未完成。源任务与运行证据见 [R1 集成验收](../reports/2026-09-22-rust-electron-rewrite/06-R1绑定集成验收.md)。

## 结论与边界

- PDFium 几何与 lopdf 源字节必须来自同一不可变输入。绑定数量相等只说明数量相等，不能证明源字节、Form 实例和对象几何一致。
- 对象 ID 相同不代表绑定仍有效。内容流原地改写会使旧源跨度指向新文字；需要在修改前验证绑定所依赖的源状态。
- 提取出的 Unicode 正确不代表画面字形正确。ActualText 和 ToUnicode 可以返回正确文本，而 CID/GID 映射画出另一字形。
- 单页输出正确也不代表共享资源安全。需要真实验证非目标页不变，并在固定相同排版输入和坐标后，检查同页在不同字形子集下的绘制一致性。

这些结论适用于内容流级编辑和子集字体嵌入；不构成对任意 PDF 编码、OCR、字体资源突变或完整排版语义的认证。

## 根因与证据

R1 累积review构造 `ABC → XBC` 的同ID流修改，旧补丁仍成功删掉新 `X`。修复后绑定保存 Contents 有序引用和遍历流的解码字节，apply 比对不一致即拒绝，原文档保持不变。对应行为守卫是 `engine/crates/syncpdf-pdf/tests/repair_patch_shared.rs`；新门禁不检查字体/资源语义，调用方的不可变原件约束仍有效。

真实23页论文的 fake 输出可提取中文，画面却显示 ASCII；同一首页在选择1/3页和全23页时改变。writer 的 CID 是出现顺序，子集 GID 是排序后的映射，Identity 把两个不同编号空间混为一谈。只统计CJK字符或检查ToUnicode会漏掉此类错误。

## 后续验收方法

1. 在真实原件上先绑定再编辑；混用版本另设明确失败回归。
2. 删除必须同时验证目标发生预期变化、非目标页及共享对象不变、失败时文档与队列不变。
3. 测试字体时故意使用与原 GID 排序不同的写入顺序，覆盖多批追加、不同宽度和实际内置CJK字体；同时核对Encoding、CIDToGIDMap、宽度与Unicode。
4. 用源字体或独立渲染路径检查实际墨迹；保存正确文本而错误画面的反例。测试总数、exit0、run_finished不能替代这一步。
5. 合并后用主树自己的target重新编译和运行，日志记录代码身份；子树成功只能证明子树。

本轮字体修复后，原始跨选页位图仍有差异；检查内容流发现Tm纵向定位不同，诊断副本只对齐Tm后像素完全一致。诊断归一化用于区分字形和定位原因，不能修改生产结果后宣称原始输出稳定性通过。

后续定位到字体资源从HashMap随机分配编号，而基线和容纳判断固定读取`metrics(0)`，与实际选中字形字体无关。改为稳定加载顺序并使用段内实际字体度量后，两次独立选页与全篇运行的p1/p3原始144dpi像素一致。守卫分别位于`syncpdf-font/tests/stable_font_ids.rs`和`syncpdf-typeset/tests/font_metrics.rs`；真实证据在主树`tmp/backend-repair/font-stability/real-cross-run.json`。

容纳策略变化还会改变合法的端到端预期。固定字号后，旧fake长译文不能再靠缩字号或溢出写入满足“每页出现中文”。对应测试应同时证明可容纳块真正写入、不能容纳块明确提示且源字形/位置不变，不能只删掉中文断言或把全回退当作翻译质量通过。

coverage 数字归零不能证明分区正确。本次首次候选把 p7 正文续行并入 Caption、p15 算法右侧说明并入 Code，主控查看源页后拒绝。最终只接受完整物理行或源框线/标题/贯通栏缝共同支持的窄修，并核对其余 21 页分区不变。新 Text 与已有 Formula 重叠还会重复消费源字形，必须在翻译/删除前保护；不能仅检查覆盖率。

## 流式提交必须以成功保存为界

准备好的译文不等于其所在页已删原文。R2发现把全部待处理段重放进每个快照，会在未ready页叠印译文；应显式筛选“已保存页+当前候选页”，在私有文档保存成功后才更新revision和发布事件。只测最终PDF会漏掉中间快照错误。回归需包含两个页、一页待处理而另一页已落定，以及保存失败后旧产物不变。

全回退时源像素完全保持是保护证据，不能证明有效翻译或快照隔离。用有实际目标字形的受控PDF验证事务，用全篇fake核对状态；两者结论分别记录。空白或不译reference页不应被要求出现中文，CJK自检应由实际替换内容驱动。详见[R2验收](../reports/2026-09-22-rust-electron-rewrite/09-R2源文本与Markdown验收.md)。
