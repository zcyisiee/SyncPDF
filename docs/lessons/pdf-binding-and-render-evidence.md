# PDF 绑定与渲染必须分别举证

本条提炼已完成的绑定审查和真实渲染失败证据；整个 Rust 后端质量任务仍未完成。源任务与运行证据见 [R1 集成验收](../reports/2026-09-22-rust-electron-rewrite/06-R1绑定集成验收.md)。

## 结论与边界

- PDFium 几何与 lopdf 源字节必须来自同一不可变输入。绑定数量相等只说明数量相等，不能证明源字节、Form 实例和对象几何一致。
- 对象 ID 相同不代表绑定仍有效。内容流原地改写会使旧源跨度指向新文字；需要在修改前验证绑定所依赖的源状态。
- 提取出的 Unicode 正确不代表画面字形正确。ActualText 和 ToUnicode 可以返回正确文本，而 CID/GID 映射画出另一字形。
- 单页输出正确也不代表共享资源安全。需要真实验证非目标页不变，并在固定相同排版输入和坐标后，检查同页在不同字形子集下的绘制一致性。

这些结论适用于内容流级编辑和子集字体嵌入；不构成对任意 PDF 编码、OCR、字体资源突变或完整排版语义的认证。

## 根因与证据

R1 累积review构造 `ABC → XBC` 的同ID流修改，旧补丁仍成功删掉新 `X`。修复后绑定保存 Contents 有序引用和遍历流的解码字节，apply 比对不一致即拒绝，原文档保持不变。对应行为守卫是 `engine/crates/syncpdf-pdf/tests/repair_patch_shared.rs`；新门禁不检查字体/资源语义，调用方的不可变原件约束仍有效。

真实23页论文的 fake 输出可提取中文，画面却显示 ASCII；同一首页在选择1/3页和全23页时改变。writer 的 CID 是出现顺序，子集 GID 是排序后的映射，Identity 把两个不同编号空间混为一谈。只统计CJK字符或检查ToUnicode会漏掉此类错误。

## 后续验收方法

1. 在真实原件上先绑定再编辑；混用版本另设明确失败回归。
2. 删除必须同时验证目标发生预期变化、非目标页及共享对象不变、失败时文档与队列不变。
3. 测试字体时故意使用与原 GID 排序不同的写入顺序，覆盖多批追加、不同宽度和实际内置CJK字体；同时核对Encoding、CIDToGIDMap、宽度与Unicode。
4. 用源字体或独立渲染路径检查实际墨迹；保存正确文本而错误画面的反例。测试总数、exit0、run_finished不能替代这一步。
5. 合并后用主树自己的target重新编译和运行，日志记录代码身份；子树成功只能证明子树。

本轮字体修复后，原始跨选页位图仍有差异；检查内容流发现Tm纵向定位不同，诊断副本只对齐Tm后像素完全一致。诊断归一化用于区分字形和定位原因，不能修改生产结果后宣称原始输出稳定性通过。

后续定位到字体资源从HashMap随机分配编号，而基线和容纳判断固定读取`metrics(0)`，与实际选中字形字体无关。改为稳定加载顺序并使用段内实际字体度量后，两次独立选页与全篇运行的p1/p3原始144dpi像素一致。守卫分别位于`syncpdf-font/tests/stable_font_ids.rs`和`syncpdf-typeset/tests/font_metrics.rs`；真实证据在主树`tmp/backend-repair/font-stability/real-cross-run.json`。

容纳策略变化还会改变合法的端到端预期。固定字号后，旧fake长译文不能再靠缩字号或溢出写入满足“每页出现中文”。对应测试应同时证明可容纳块真正写入、不能容纳块明确提示且源字形/位置不变，不能只删掉中文断言或把全回退当作翻译质量通过。

coverage 数字归零不能证明分区正确。本次首次候选把 p7 正文续行并入 Caption、p15 算法右侧说明并入 Code，主控查看源页后拒绝。最终只接受完整物理行或源框线/标题/贯通栏缝共同支持的窄修，并核对其余 21 页分区不变。新 Text 与已有 Formula 重叠还会重复消费源字形，必须在翻译/删除前保护；不能仅检查覆盖率。

## 流式提交必须以成功保存为界

准备好的译文不等于其所在页已删原文。R2发现把全部待处理段重放进每个快照，会在未ready页叠印译文；应显式筛选“已保存页+当前候选页”，在私有文档保存成功后才更新revision和发布事件。只测最终PDF会漏掉中间快照错误。回归需包含两个页、一页待处理而另一页已落定，以及保存失败后旧产物不变。

全回退时源像素完全保持是保护证据，不能证明有效翻译或快照隔离。用有实际目标字形的受控PDF验证事务，用全篇fake核对状态；两者结论分别记录。空白或不译reference页不应被要求出现中文，CJK自检应由实际替换内容驱动。详见[R2验收](../reports/2026-09-22-rust-electron-rewrite/09-R2源文本与Markdown验收.md)。

## 部分删除必须保留文本状态与名义推进

R3全篇保留内容审计发现p14有35个未删字符移位，虽然绑定、qpdf和新增译文测试都通过。根因是重建TJ数组时丢掉原数值间距，且简单字体间接Widths未解引用，回退1000造成推进错误。守卫必须包括部分/尾部/全部删除之后的保留字形原点、同文本矩阵上的下一次Tj，以及Tc/Tw/Tz和quote状态。

墨迹bbox宽不是名义advance。Type0宽度属于后代CIDFont；Type3还要考虑FontMatrix。源宽度未知时应明确拒绝发布，不能猜。全篇审计按Unicode、位置、字号和颜色核对保留内容，能发现跨段共享同一次TJ导致的破坏。详见[R3验收](../reports/2026-09-22-rust-electron-rewrite/10-R3固定字号与排版验收.md)。

## 真实翻译 MVP 要能复用译文独立编译

模拟译文能检查工程保护，却不能证明模型遵守Markdown协议。真实全文中有坏转义和少量持续不合规块；已就绪排版也不等于对应页已提交。验收须区分首个typeset、PageReady和最终发布。

只读复制真实缓存、重新校验、跳过全部模型请求的重编译路径，使排版修复可快速复验；未命中块仍明确回退，不能通过伪造译文或放宽校验填满结果。普通数字、公式源绘制和带链接引用需要不同放置能力，不能将全部atom等同于公式，也不能未经几何支持就一起解除保护。详见[MVP验收](../reports/2026-09-22-rust-electron-rewrite/12-MVP真实翻译验收.md)。

R4的40个原子回退实际只有数字引用和普通数字，没有Formula。必须先检查kind、源span、样式和真实链接关联，而不是按warning名称选方案。无链接的文本引用可以在精确源范围证明后正常塑形；有链接的引用仍须目的地身份与目标点击几何。未含链接的论文结果不能证明链接重排正确。

## 整行外接框不是逐字形碰撞证据

同一行最低的下伸部和下一行最高的上伸部可能处于不同横向位置。直接对整行bbox判交会错误拒绝固定字号结果；R4有7段在逐glyph墨迹框复核后可容纳，逐字形坐标、字号、行距、断行完全不变。正确做法是整行框初筛，再以字形墨迹框/原子矩形作保守确认，并检查可能跨越多行的高字形；不能通过加大容差或缩字掩盖误判。

验收同时保留“整行框相交但字形互不相交”和“真正字形相交”的测试，未知轮廓继续用保守字体度量。最终仍需在写入PDF上核对位置、字号、源保护和可见渲染，不能仅用排版内存结果作为交付证明。

## 用户字号选择与自动缩字不是同一件事

明确请求的字号缩放应在源解析/翻译单元之后只作用于目标排版规格，逐run同比调整；行距保存为倍数并由目标段落主字号推导。不要修改源IR来改变排版，否则可能改变原子归属、删除依据或译文缓存身份。fit阶段仍保持该请求，不因失败继续缩小。R5在同一158段真实缓存上用0.9字号/1.3x行距，147段写入、0原成功段退化；另核对保护原文不变，见[MVP R5验收](../reports/2026-09-22-rust-electron-rewrite/12-MVP真实翻译验收.md#r5-relative-typography)。

“校验拒绝”也不自动等于“模型译错”。R5曾确认同外观StyleId换序和短标题英文术语比例导致误拒；R6按用户要求放宽样式布局并删除语言比例门槛，保留内容身份与写回安全检查。必须区分源表示限制、模型问题和校验误判；没有保存的失败回包不能凭错误码还原。

## 真正的链接样本能推翻数量检查的“通过”

按YAGNI先跑用户的CCS 3764样本，发现319个链接和全部目标虽未丢失，却有22个点击框停在旧位置，罩住无关中文或空白。原子检查对无atom段早退，恰好漏过普通表/节交叉引用。必须同时核对目标、点击框内的引用文字及译文位置；不能仅凭Annots数量、目标可解析或源字符保留宣称链接正确。p7的`Table 2`旧框罩住译文“下”字是可视反例。

同次实测已证明149秒首块编译早于201秒翻译结束，但当时没有译后layout轮次，不能把静态安全frame当动态bbox。先保留这种可证伪的真实证据，再做针对性修复，不为假设需求扩建框架。详见[CCS验收](../reports/2026-09-22-rust-electron-rewrite/12-MVP真实翻译验收.md#ccs3764-yagni-test)。

## 先审正文覆盖，再报下游回退数

用户复核CCS最终PDF指出第2页仍有4块完整英文。实际原因是正文框与嵌套Formula共享字形，翻译前整段标为`not_replaced`；不在157个送译块及3个排版回退之内。全篇另有40个源区域冲突和1页覆盖缺口，最终事件已明确提示，交付却突出较小的回退数，造成严重误导。

必须分开核对正常策略保留、翻译前阻断、模型/校验失败、排版失败。源字符位置不变是安全证据，不是翻译覆盖证据；缺字修复也不等于支持嵌套公式放置。未送译块没有真实译文缓存，缓存复排不能弥补。正文覆盖不合格时，应在交付开头明确标出，而非淹没在“部分结果/保护内容”中。详见[重大缺陷及第2页逐块证据](../issues/rust-inline-formula-coverage.md)。

## 先分清非空间失败，再回收译后净空

R7复用同一157段真实缓存，69回退降至3：数学缺字需可复现的精确Unicode字体回退，微小负侧承需纠正起笔，链接需锚点和原子提交，均不能靠扩bbox解决。源绘图还要正确消费`n`并应用Form BBox：裁剪背景的巨大原始路径框不是实际页面障碍。`Rect::new`会归一化端点，求交必须先判断是否分离，否则空交会变成新的假障碍。

动态bbox必须使用“不可变源障碍－已替换源字形＋已接受译文墨迹”，而不是在已删原文的输出上反复重绑。有限轮同栏回收可移动基线，但不能占用保留表格/图片；无可用空间就保持明确回退。保存前的初始排版fallback可被成功精修取代，保留内容检查与消费端都应取最新段状态，而非把所有历史fallback当最终事实。

字体验收可在相同字号/原点下用完整原字体独立绘制，与交付PDF子集字形逐墨迹比对；仅检查gid非零或Unicode可提取不够。R7对30个数学字形做此对照，并确认第3页保留图区域像素完全一致。链接验收同时检查Dest/A、目标标签和新点击框；旧缓存重复数字无法消歧时仍回退。证据与限制见[R7验收](../reports/2026-09-22-rust-electron-rewrite/12-MVP真实翻译验收.md#ccs3764-r7)。

## 公式保护应保留源绘制，不能吞掉所属正文

正文大框包含行内公式小框是正常嵌套。先证明公式全部字形归属一个可译段、源clip不含其它文字/图片/跨界路径，再以原子随译文重排；不能简单去掉保护门禁。上下标须沿正文基线归一化分行，否则一个公式会拆成多个假段。原尺寸公式高于普通文字时，只增加碰撞处必要行距；正文和公式都不为通过而缩小。

只给源页套clip会留下隐藏文字，甚至让嵌套图片Form重复出现在文本提取中。公式副本必须删除无关文本、隔离嵌套Form，保留公式原字体/路径；原图不能被修改。回归同时核对公式移动一次、邻近正文和深层图片文字各保留一次。公式内引用的点击框按原子位移更新，不能用普通文本匹配猜位置。

在CCS实跑中，数字单位正则将`2 shows`的s误作秒，补词界后11块源hash变化；应让真实模型补译，不能伪造缓存兼容。第20页漏检的带标签子标题，只凭单行、紧邻图表和居中证据恢复，并利用面板宽度排版，不能整体扩大保护区域“消掉”coverage gap。

模型回包中的正文语法错误与流边界损坏必须分开。闭合ID可靠时，坏块可走现有有界补译，其余有效块继续流式交付；无可靠闭合边界或通道失败仍中止，不接收猜测修复文本。坏块不缓存，耗尽后计为未完成。

最终验收必须同时列出送译前冲突、覆盖缺口和下游回退，并检查保存后的实际PDF。此次193块完整写入，94个公式渲染与保护内容/链接通过；真实请求、缓存复排及失败尝试分别记账，见[修复验收](../reports/2026-09-22-rust-electron-rewrite/12-MVP真实翻译验收.md#inline-formula-coverage)。
