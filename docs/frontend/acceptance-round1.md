## 问题清单

### ACC-001 · 窄中栏工具条挤压、文字越框（P1，已复现）

**步骤**：打开上述文档进度页，保持左右栏展开，将浏览器视口宽度调至 1200 CSS px。

**实测**：视口 1200×796；工具条 clientWidth=526、scrollWidth=564、clientHeight=43。“上一页/下一页”按钮 clientHeight=22、scrollHeight=35；“段落框/版面框”按钮 clientHeight=24、scrollHeight=34。对照宽视口 1496×796 时工具条宽 822、scrollWidth=822。

**定位**：`web/src/components/preview/PreviewToolbar.tsx` 固定 `h-11` 的单行 flex，按钮固定高度但文字可换行；没有窄栏溢出布局策略。

**建议验收**：中栏 360/480/640/820px，右栏展开/收起、对照模式、三位数页码、质量状态和下载区域均测试；文字不逐字折行、不越界，功能入口不丢失。允许工具组有序换行或收进更多菜单，不能仅裁切隐藏。若 360px 不支持，应明确最小宽度并限制分隔条。

### ACC-002 · profile 概念不明、空态没有可操作出口（P1，已确认）

**实测**：`GET /api/v1/profiles` 返回 `[]`；页面显示“没有可用 profile”，开始翻译禁用。提示只给 `<store_base>` 路径及 PUT API，无创建入口。

**含义**：profile 是服务器端保存的一组执行配置，用于指定调用哪个翻译脚本以及可选审校脚本；不是用户账号，也不是 PDF 的版式类别。浏览器传配置 id，命令由服务端解析。

**定位**：`web/src/components/jobs/StartJobCard.tsx`；`web/README.md` 的 profiles 小节明确当前不做编辑器。

**建议验收**：用户看到“翻译配置”等易懂名称及用途说明；空态能直接进入创建/配置引导，创建成功后可选中并启动任务。保留脚本白名单和敏感信息不下发的安全边界，不能简单放开任意命令输入。

**附加待测**：profile API 请求失败/加载中，目前代码默认空数组且没有独立查询错误显示，可能被误解为“没有配置”；应使用故障注入验证并区分三种状态。

### ACC-003 · 识别框无法按类别筛选（P1，能力缺口已确认）

**现状**：工具条仅有“段落框 / 版面框 / 关”，不是类别筛选。`BboxLayer` 对传入 boxes 全部绘制。

**数据证据**：当前文档第一页 parse geometry 有 15 个实体，标签为 text×5、page_footnote×4、title×3、author×1、page_number×1、aside_text×1。标签并非完全缺失；证据保存在 `tmp/acceptance-round1/geometry-parse-page1.json`。

**建议验收**：按当前数据实际类别展示中文名、原始标签、色标和数量；支持逐类切换、全选、全不选。隐藏的框不能继续拦截点击，显示筛选不能修改识别结果或翻译选择。翻页后筛选保持；跨文档行为明确。

**边界**：参考图来自 PP-DocLayoutV3，当前数据标签集合不必相同，不能硬凑图中的 19 类；计数是当前页还是全篇需要明确。

### ACC-004 · PDF 仍为单页切换，不支持纵向连续阅读（P1，能力缺口已确认）

**现状**：`PreviewArea.tsx` 的 PreviewPane 挂一个 PdfCanvas，页码改变替换当前页。浏览器当前译文模式只有一个 canvas。`web/README.md` 明确将连续滚动排除在 v1 范围外。

**建议验收**：多页按上到下排列，滚动到页尾自然接下一页；工具条页码随当前可见页更新，输入页码可定位；用当前 58 页文档验证稳定滚动，避免一次渲染全部高清画布。bbox 与对应页面同步加载且不串页。

### ACC-005 · 缺少 PDF 内部缩放及 Mac 触控板捏合（P1，能力缺口已确认；物理手势待人工测）

**现状**：`PreviewArea.tsx` 只有适宽缩放（0.5–3 钳制）；`PreviewToolbar.tsx` 缩放读数只读，没有用户缩放控制。本轮没有实际操作物理触控板，不声称已完成手势验收。

**建议验收**：提供放大、缩小、适宽、比例显示；Mac 触控板捏合只缩放 PDF，不把整个应用 UI 一起放大；缩放锚点稳定，bbox 不漂移。普通双指上下滑动仍为滚动，缩放后允许平移查看，Chrome/Safari 分别人工验收。

### ACC-006 · bbox 默认无边框、类别视觉无法区分（P2，已确认）

**实测**：浏览器未选中 bbox 的 computed stroke 为 `rgba(0, 0, 0, 0)`，fill 为强调色约 8% 透明度。

**原因**：`web/src/components/preview/BboxLayer.tsx:198` 明确使用 `fill-tint stroke-transparent`；只有 hover 或选中才有描边，不是解析坐标缺失。

**建议验收**：参考用户图片，默认有可见类别色描边和低透明度填充，正文清晰可读；类别图例与框颜色一致；hover/选中/编辑手柄可区分；缩放时边框不过粗或消失。仍须保留唯一 bdt 入口，不另建 viewer 产品入口。

**设计冲突**：`web/README.md` 当前要求“禁止第二个强调色”，与多类别配色需求冲突。实施前需将 bbox 语义类别色列为设计规范中的明确例外，不能继续按旧验收标准否决新需求。
