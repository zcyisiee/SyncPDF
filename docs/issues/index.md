## 维护规则

- **必须有证据**：写进本目录的结论要能追到真实运行数据、实验或行为测试，不写推测。区分「已验证」与「待验证」。
- **区分路径**：结论要指明它作用于哪条代码路径。本项目存在多条相似但行为不同的合成/编译路径（例如预览与导出），混为一谈会得出错误结论。
- **不写已实现的方案**：候选修复就是候选，明确标注「未实施」；实施后把该篇改为已修复或删除，并把事实写进对应的参考文档。
- **不扩大本目录**：只有严重到值得单独跟踪的问题才建篇；一般缺陷进测试或代码注释。
