## 历史根因

- `syncpdf-core/src/ir.rs::RegionKind::translatable()`将Formula列为不可译区域。
- `syncpdf-pipeline/src/stages/paragraph.rs::analyze_page()`先收集不可译区域内的源字形；任一正文段共享其中一个字形，即将整个段落设为`Translatable::No { reason: "protected_source_overlap" }`。
- 布局检测中的正文大框包含行内公式小框是正常嵌套。旧实现缺少可靠的行内公式归属/原子放置，安全门禁将“保留公式”扩大为“整段不送译”。第2页不是布局模型把全文识别成英文不可译区。
- `run.rs`把这些块送入not_replaced分支；翻译器只收到其余可译块。`fallbacks`只描述下游失败，不覆盖翻译前排除项。整体ok已会因冲突/覆盖缺口置false，但交付解读没有反映此严重性。

STIX数学字体回退解决已送译文本中的数学Unicode缺字，不等于已实现行内公式源绘制；增加排版框、重试同一缓存或恢复语言比例校验均不能修复该问题。

## 原修复要求（已实施）

1. 优先建立正文与嵌套行内公式的唯一源归属及可安全排入译文的原子表示；不能直接移除重叠保护，否则有重复删除或破坏公式风险。
2. 将正常策略保留、应译但翻译前阻断、模型/校验失败、排版失败分开汇总。交付必须检查实际正文覆盖，不能以保留原文不变或缓存内成功率证明完整翻译。
3. 修复后这些块需要真正送译；旧157段缓存没有它们，不能用缓存复排冒充补译。先用第2页4块验收，再核查全篇40个阻断候选及覆盖缺口。
