# Rust 后端：绕排段落被拆成两段

状态：**已记录，暂缓修复**（2026-09-25 用户决定：学术论文少见绕排，排版特殊，之后再修）。

## 现象

正文段落在浮动体（表格/图 + 题注）旁被收窄、浮动体下方恢复全宽时，同一段落被拆成两个翻译单元：上半截在窄栏内独立翻译排版，下半截单独成段，句子被从中间切开（如 "in-" / "terpretability"）。

## 证据

2604.03136v6.pdf（`syncpdf-cli inspect --page 6/8 --paragraphs`）：

- P06-006（107.7–305.6 宽，右侧 Table 2 与题注）+ P06-009（108.0–498.4 全宽，首词 "terpretability."）应为一段。
- P08-010（右侧 Table 3 题注）+ P08-013（首词小写 "and GPT…"）应为一段。
- 反例：P08-009 → P08-010 间有段距（约 14pt），为两个独立段落。
- 版面可视化：`tmp/paper-iteration/layout-viz/2604-layout.pdf`。

## 根因

PP-DocLayoutV3 按实例输出矩形，mask 限于各自框，没有跨两部分的检测；段落切分按区域进行，跨区域永不合段。仅改多边形不能解决。

## 候选方案 A（未实施）

1. 段落阶段：相邻两区域的末段/首段满足「同段续行（基线差、无缩进）+ 行距连续 + 一侧对齐另一侧明显更宽 + 较窄部分旁有其它区域（浮动体）」时合成一个翻译单元，并记录各源部分外接框（band）。
2. 排版阶段：Knuth–Plass 已支持逐行宽度（`widths[i]`），但 `layout` 目前只传首行/其余两档且所有行共用一个 bbox；需按预估基线把每行映射到所在 band 取横向范围，放置与越界检查也按行范围。
3. refinement 的移动/整栈重排按矩形处理，band 为绝对坐标；移动后靠障碍碰撞检查 fail-closed。

难点：`Paragraph` 需新增字段（约 20 处测试字面量），排版器与页内借位均以矩形为前提。
